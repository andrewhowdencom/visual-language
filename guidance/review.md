# Review before delivery

Run this review on the rendered experience. Record what was checked and what remains uncertain.

## Task and hierarchy

- [ ] The primary task is clear without reading explanatory documentation.
- [ ] Each screen or region has one obvious next useful action.
- [ ] Empty, loading, error, success, selected, disabled, and destructive states are covered where applicable.
- [ ] Color intensity follows importance; broad surfaces do not compete with task content.

## Accessibility

- [ ] Ordinary text meets at least 4.5:1 contrast, large text 3:1, and meaningful non-text controls or state boundaries 3:1 where WCAG 2.2 AA requires it.
- [ ] Focus is visible, order is logical, and keyboard or accessibility navigation reaches every action.
- [ ] Meaning is never conveyed only by color or motion.
- [ ] Larger text, zoom, long labels, and reduced-motion preferences are supported.

## Adaptation and platform behavior

- [ ] The smallest supported window and a wide window are both usable; transitions between them are checked.
- [ ] The layout adds useful context at larger sizes and keeps reading width comfortable.
- [ ] Android uses Material 3 roles and platform navigation or system behavior appropriately.
- [ ] Web uses semantic HTML, links, history, responsive layout, and native input behavior appropriately.

## Forms and fields

- [ ] Each field has a visible label, suitable input method, and clear required or optional status.
- [ ] Add, Save, Done, automatic saving, and leaving the screen have defined outcomes where applicable.
- [ ] Invalid input and failed saves keep the draft and show a recoverable error near the affected field.
- [ ] Cancel, Back or navigation away, and expected interruptions preserve or discard drafts as designed.
- [ ] A form remains usable with the keyboard open, large text, long labels, RTL layout, and accessibility navigation.

Use [Forms and fields](forms.md) for the full save and validation guidance.

## Color and delivery

- [ ] The chosen primary family and every derived token are recorded; unapproved exploratory colors are identified as such.
- [ ] Light and dark schemes have been checked in context, including state combinations.
- [ ] The delivery includes a decision record, platform mapping, and any known guidance gaps.

For a physical space, also review the [site-specific constraints and physical samples](physical-space.md) before purchase or installation.
